# Qevli V37 — all 10 production foundations

V37 is an additive upgrade over V36. Existing authentication, public feed, official-source engine, stories, groups, calls, live, search, recommendations, moderation, Redis/BullMQ boundaries and admin systems are preserved.

## 1. Realtime
A persistent Server-Sent Events endpoint is available at `/api/realtime/stream`. The dashboard consumes it and falls back to `/api/realtime/poll` when SSE is unavailable. This gives browser clients a persistent realtime transport without requiring a separate WebSocket server.

## 2. Media
Local uploads remain the default and require no R2 account or card. `/api/uploads` stores development media under `public/uploads`. Existing S3/R2 presigning remains optional for production. Uploads are size/type limited and rate limited.

## 3. Stories
Stories already support text/image/video, 24-hour expiry and views. V37 adds scale indexes and keeps the existing API.

## 4. Groups
Existing group creation, public/private membership and group messaging APIs remain in place. V37 adds scale-oriented indexes and realtime event infrastructure.

## 5. Qevli Video
Existing post video creation/playback/reaction/comment/repost support remains. Local media can be used for development; a production CDN/object store can be enabled later.

## 6. Messaging and calls
Existing one-to-one messages and LiveKit call APIs remain. Realtime SSE now surfaces new messages/notifications. LiveKit credentials remain optional until calls are used.

## 7. Moderation and anti-abuse
Existing reports, moderation cases, appeals and block controls remain. V37 adds a reusable Redis-backed rate limiter with an in-memory fallback, currently protecting media uploads and post creation.

## 8. Search
Existing people/posts/company/hashtag/web search remains. It continues to use configured web search when available and local database search otherwise.

## 9. Recommendations
Existing recommendation feedback storage and recommendation API remain. The feed/ranking layer can use engagement, freshness and social affinity without requiring a paid API.

## 10. Production infrastructure
Redis/Upstash, BullMQ, worker queues, health endpoints, admin network observability, official-feed cron and database indexes are preserved. V37 adds the persistent realtime transport and scale indexes.

## Environment
Core local variables remain:

```env
DATABASE_URL=
AUTH_SECRET=
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

Optional infrastructure variables can be enabled later:

```env
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
REDIS_URL=
S3_ENDPOINT=
S3_BUCKET=
S3_ACCESS_KEY_ID=
S3_SECRET_ACCESS_KEY=
S3_REGION=auto
CDN_BASE_URL=
LIVEKIT_API_KEY=
LIVEKIT_API_SECRET=
NEXT_PUBLIC_LIVEKIT_URL=
QEVLI_CRON_SECRET=
```

**R2 is not required. No online card is required for V37 local development.**

## Upgrade

```powershell
npm install
npx prisma generate
npx prisma migrate deploy
npm run dev
```

For background jobs, only when Redis is configured:

```powershell
npm run worker
```

Never use `prisma migrate reset` on the real Qevli database.
## Storage without R2
Qevli V37 defaults to local media storage for development. Cloudflare R2/S3 is optional and no card or R2 account is required to run the local app. Keep `QEVLI_STORAGE_MODE=local` while developing.

## Official source registry
Admins can add, enable, disable, and delete official feed sources directly at `/admin`. The curated source seed is optional: `npm run seed:official-sources`. Enabled sources are synchronized automatically by the official-feed cron.

## Environment loading fix
V37.1 loads `.env` for Prisma and standalone `tsx` seed/sync scripts. `dotenv` is included as a dependency.
